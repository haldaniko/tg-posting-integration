# Telegram бот публикации новостей

Отдельный проект редакторского бота для `fxlfm` и будущих сайтов. Бот работает в личном чате, хранит черновики в своей БД и вызывает только `/api/bot/v1/` сайта. Данные на сайт отправляются после кнопки «Опубликовать». Рабочий режим — Telegram polling.

## Быстрый запуск (Python 3.12)

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите Telegram bot token. Узнайте числовые Telegram user ID редакторов и добавьте их в allowlist.
2. Создайте виртуальное окружение: `py -3.12 -m venv .venv` (Windows) или `python3.12 -m venv .venv` (Linux). Активируйте его.
3. Установите проект: `python -m pip install -e '.[test]'`.
4. Скопируйте `.env.example` в `.env`. Заполните `TELEGRAM_BOT_TOKEN`, `ALLOWED_USER_IDS` и `FXLFM_INTEGRATION_TOKEN`. Последний должен совпадать с `BOT_INTEGRATION_TOKEN` в локальном `.env` **сайта**; это отдельный ключ, не Telegram token и не JWT администратора. Локальный `.env` бота уже может содержать скопированный ключ, если проект был подготовлен в этом рабочем каталоге. Не коммитьте `.env`.
5. Запустите локальный backend `fxlfm` и проверьте `FXLFM_API_BASE`. Для backend на хосте это обычно `http://127.0.0.1:8000/api/bot/v1/`. Для бота в Docker на Windows используйте `http://host.docker.internal:8000/api/bot/v1/`.
6. Запустите `tg-posting-bot` или `python -m posting_bot.main`. Откройте личный чат и отправьте `/start`.

Команды: `/new` — начать или продолжить активный черновик, `/drafts` — последние черновики и статьи, `/cancel` — отменить активный черновик. Кнопки меню выполняют те же действия. Во время основного текста можно отправить несколько сообщений и нажать «Текст готов». Перед публикацией доступны правки всех полей.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `ALLOWED_USER_IDS` | Числовые ID редакторов через запятую; проверяются при каждом действии |
| `DATABASE_URL` | SQLAlchemy URL; SQLite локально или `postgresql+psycopg://...` для production |
| `PHOTO_DIR` | Постоянный каталог временных фото; нужен общий volume при контейнерном запуске |
| `FXLFM_API_BASE` | Базовый URL `/api/bot/v1/` с завершающим `/` |
| `FXLFM_INTEGRATION_TOKEN` | Ключ интеграции сайта из `BOT_INTEGRATION_TOKEN` сайта |
| `SITES_JSON` | Дополнительные сайты с тем же контрактом API |

Пример второго сайта: `SITES_JSON=[{"id":"second","name":"Second","api_base":"https://second.example/api/bot/v1/","token_env":"SECOND_INTEGRATION_TOKEN"}]`. Задайте `SECOND_INTEGRATION_TOKEN` отдельно в окружении. Категории и авторы каждый раз берутся с выбранного сайта; сохраняются их slug, а не общие числовые ID. Чтобы подключить иной API, реализуйте интерфейс `SitePublisher` из `publisher.py` и зарегистрируйте новый адаптер в `main.py`; диалог менять не требуется.

Для нового экземпляра сайта создайте свой длинный случайный `BOT_INTEGRATION_TOKEN`. В `fxlfm` настройте `SITE_URL` на публичный адрес сайта (в локальной разработке — адрес, доступный браузеру), перезапустите backend и примените миграции. Production compose сайта применяет `0011_bot_integration` при старте.

## Docker

Скопируйте `docker-compose.example.yml` в `docker-compose.yml`, заполните `.env`, задайте длинный `POSTGRES_PASSWORD` и запустите `docker compose up --build -d`. В compose БД PostgreSQL и каталог фото используют отдельные volumes. Запускайте только один экземпляр polling бота на один Telegram token. Для изменения схемы существующей БД нужны контролируемые миграции; автоматическое создание таблиц рассчитано на новую установку.

## Что происходит при сбое

Бот сохраняет черновик после каждого шага и `external_id` для каждой доставки до первого запроса на сайт. При сетевом сбое он автоматически делает одну повторную попытку: запрашивает `GET articles/<external_id>/`, затем безопасно повторяет создание, загрузку фото и/или публикацию. Если и она не удалась, редактор может нажать «Повторить». Все попытки используют прежний `external_id`. После первой отправки правки создают новую версию с новым ID — это **новая статья**. Фото новой версии выбирается снова.

Фото скачивается через Telegram Bot API в `PHOTO_DIR`, проверяется по размеру и сигнатуре, передаётся бинарным multipart файлом в API сайта. После успешной публикации или отмены локальный файл удаляется. При ошибке загрузки фото публикация не запускается; кнопка «Повторить» продолжает с прежним ID. Если процесс завершился во время публикации, откройте `/drafts` и повторите; после защитной паузы попытка восстановится.

Логи не содержат токены или тело ответа сайта. Коды 400, 403, 404 и 409 преобразуются в понятные сообщения. При отказе сайта статья не публикуется через административный API.

## Проверка

Запустите `python -m pytest -q`. Тесты используют поддельный HTTP API и временную SQLite БД, проверяют диалог, allowlist, рестарт, повторные кнопки, повторную публикацию и ошибку фото. Для полной проверки с реальным backend запустите локальный `fxlfm`, проверьте `GET options/` с ключом и создайте тестовую статью **только в локальном окружении**. Никогда не тестируйте публикацию на живом сайте без разрешения владельца.
